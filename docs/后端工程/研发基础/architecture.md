# 架构设计 🏗️

> 整理常见架构设计模式

***

## 系统架构

### 单体架构
最简单的方式，所有功能在一个应用内

**优点**：简单、易部署、易测试
**缺点**：难以扩展、维护困难

### 微服务架构
将功能拆分为独立服务

**优点**：独立部署、易扩展、技术多样性
**缺点**：复杂度高、服务治理难

### Serverless 架构
使用云函数，无需管理服务器

**优点**：按需付费、自动扩展
**缺点**：冷启动延迟、供应商锁定

## AI 系统架构

### RAG 架构
检索增强生成

```bash
用户输入 → 检索 → 上下文 → LLM → 回答
     ↓
向量数据库
```

### Agent 架构
智能体系统

```bash
用户输入 → 规划器 → Agent网络 → 工具 → 回答
     ↓
记忆系统
```

### MLOps 架构
机器学习运维

```bash
训练 → 评估 → 部署 → 监控 → 迭代
```

## IoT 架构

### 典型智能家居架构
```bash
设备 → 网关 → MQTT Broker → Home Assistant → 前端
```

### ESP32 设备架构
```bash
传感器 → ESP32 → Wi-Fi → 云服务/本地
```
