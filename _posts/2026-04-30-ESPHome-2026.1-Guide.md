## 1. 更新内容逐条解析

### 1.1 ESP8266 堆内存从 <10KB 提升到 30KB+ 的原理

**背景：**
ESP8266 实际可用堆内存在近乎空配置下约 45KB，但近年来随着 ESPHome 功能增加、代码库扩大，真实配置下运行时堆经常跌破 10KB，导致设备不稳定、无法更新。

**实现原理（months of work，Open Home Foundation 资助两位全职开发者）：**

| 优化手段 | 说明 | 内存节省 |
|---|---|---|
| **消除堆抖动（heap churn）** | 系统性消除不必要的动态分配，`malloc/free/realloc` 仅在 setup 阶段调用，运行期间不再触发 | IRAM 节省 ~6KB |
| **heap 函数从 IRAM 移至 Flash** | 配合上述优化，heap 函数不再常驻 IRAM，释放 IRAM 空间 | ~6KB IRAM |
| **`object_id` 不再存入 RAM** | 每个 entity 的 `object_id` 字段不再存储在 RAM 中 | ~886 字节（37 entities）至 ~3.6KB（800 entities） |
| **StaticVector / FixedVector 替代 std::vector** | 编译期已知大小的容器直接用静态/栈分配 | 运行时 heap 分配归零 |
| **`const char*` 替代 `std::string`** | 静态字符串直接用指针，不再 heap 分配 | 持续性节省 |
| **预分配缓冲区** | 热路径中的缓冲区预先分配，不动态申请 | 消除运行时分配 |
| **未使用 Serial 对象被排除** | 未使用 `Serial`/`Serial1` 的设备不再链接相关代码 | 32-64 字节 RAM |
| **未使用 waveform 代码被排除** | 未使用 `esp8266_pwm` 的设备不再链接波形代码 | 596 字节 RAM |

**效果：**
> ESP8266 可用堆从 **under 10KB 提升到 over 30KB**（实测配置），从根本上改变了 ESP8266 的可用性。设备不再动不动就 OOM，原先不稳定的配置变得可靠。

### 1.2 ESP32 默认框架切换到 ESP-IDF（固件体积缩小 40%、编译提速 2-3 倍）

**背景：**
2024年底 ESPHome 完成 ESP-IDF 4.x → 5.x 的过渡，2025年又升级 Arduino 2 → Arduino 3，两次升级叠加导致 ESP32 内存占用显著增加。ESPHome 将 Arduino 作为 ESP-IDF 的一个组件运行，而非独立框架，从而获得统一控制权。

**ESP-IDF 优势：**

| 指标 | 改善幅度 |
|---|---|
| 固件体积 | 缩小 **up to 40%** |
| 编译时间 | 提速 **2-3 倍** |
| 运行时代码优化 | 更贴近硬件，性能更好 |
| 新功能支持 | ESP32 新特性优先在 ESP-IDF 提供 |

ESP-IDF 5.5.2 版本还带来了 libc 等组件的编译器优化，进一步减少约 35KB (~4%) Flash 占用。

**补充优化（ESP32）：**

- **IRAM 节省 ~6KB**：heap 函数从 IRAM 移至 flash（同 ESP8266）
- **零拷贝消息处理**：protobuf 消息零拷贝 + `object_id` 从协议中移除 → 每包可承载 entity 数从 24 增至 34（**+42%**）
- **lwIP 直调**：绕过 VFS 层直接调用 `lwip_read()/lwip_write()`，降低 API/async TCP/语音助手延迟
- **PSRAM 设备 IRAM 节省**：ESP32 r3.0+ 且有 PSRAM，设置 `minimum_chip_revision: "3.0"` 可额外节省 ~10KB IRAM
- **Camera 性能**：帧率提升 ~10%，空闲 CPU 占用降低 ~50%，延迟降低
- **批量消息减小 33%**：batch items 从 12 字节降至 8 字节

**受影响的 ESP32 芯片型号（默认切换）：**
- ESP32
- ESP32-C3
- ESP32-S2
- ESP32-S3

> **注意：** ESP32-C6、ESP32-H2、ESP32-P4 等新型号原本就默认 ESP-IDF，不受影响。

### 1.3 WiFi 自动漫游配置

**这是多年来最被请求的功能。**

**解决的问题：**
设备连接 WiFi 后，即使附近有信号更强的 AP，也一直粘在原来的 AP 上不会切换。典型场景：
- AP 重启 → 设备连上了远端 AP，原 AP 恢复后也不切回来
- 断电恢复 → 哪个 AP 先恢复就连哪个，往往是最差的
- Improv 配网 → 可能选了信号最差的 AP

**实现机制：**
- 默认**启用**，连接后每 5 分钟最多扫描 3 次
- **信号已经很好时跳过扫描**
- **仅在发现明显更好的信号时才漫游**（用户无需理解 RSSI 阈值）
- 如果用户已配置 802.11k 或 802.11v 漫游，post-connect roaming 会自动关闭

> 适用于**静止设备**，设计策略是**保守且安全**。

### 1.4 强制 API 加密和 OTA SHA256 认证

**API 加密（替代 password）：**
- `api: password:` 认证方式已被**移除**（自 2022年5月 deprecated）
- 必须迁移至 `api: encryption: key:`，使用 Noise-based 加密协议，同时提供**身份验证 + 流量加密**
- 生成密钥：`openssl rand -base64 32`

**OTA SHA256 认证（替代 MD5）：**
- MD5 认证支持已**移除**，SHA256 强制启用，防止协议降级攻击
- **2025.10.0 之前的 ESPHome 版本无法 OTA 更新到 2026.1.0+**
- 多系统环境需确保所有系统均为最新版本

## 2. 升级指南

### 步骤一：备份配置

```bash
# 备份所有配置文件
cp -r /config/esphome/ /path/to/backup/esphome_backup_$(date +%Y%m%d)/
```

### 步骤二：更新 ESPHome

```bash
# Docker 方式
docker pull esphome/esphome

# 或 pip 方式
pip install --upgrade esphome
```

### 步骤三：迁移 API 认证（必须）

**旧配置（有 `password:`）：**
```yaml
api:
  password: !secret api_password
```

**新配置（使用 encryption）：**
```yaml
api:
  encryption:
    key: !secret api_encryption_key
```

生成新密钥：
```bash
openssl rand -base64 32
# 输出类似：5HjC8QmNLZXsH+2r7sK3RqRxNz6YvX9P1mA3Q4kLmU=
```

### 步骤四：如需使用 Arduino 框架（显式声明）

```yaml
esp32:
  board: esp32dev
  framework:
    type: arduino  # 显式指定，继续使用 Arduino
```

### 步骤五：清理构建缓存并重新编译

```bash
# 清理指定配置的构建缓存
esphome clean your-device.yaml

# 重新编译
esphome compile your-device.yaml
```

### 步骤六：验证与刷写

```bash
# 首次刷写（推荐有线方式）
esphome upload your-device.yaml

# 后续 OTA 更新
esphome upload your-device.yaml --upload-port IP地址
```

## 3. 配置变更注意事项（Breaking Changes）

| 变更项 | 严重度 | 说明 |
|---|---|---|
| **`api: password:` 已移除** | 🔴 阻塞 | 配置有 `password:` 的设备无法编译。必须迁移至 `encryption: key:` |
| **ESP32 默认框架切换为 ESP-IDF** | 🟡 注意 | ESP-IDF 不兼容的组件（`heatpumpir`、`midea`、WLED Effect）需显式设 `type: arduino` |
| **OTA 必须 SHA256** | 🔴 阻塞 | 2025.10.0 之前版本无法 OTA 到 2026.1.0+ |
| **ESP8266 未使用 Serial 对象被排除** | 🟢 低 | 直接使用 `Serial`/`Serial1` 的 lambda 需加 `enable_serial: true` |
| **ESP8266 未使用 waveform 代码被排除** | 🟢 低 | 直接使用 Arduino 波形函数的 lambda 需添加 `esp8266_pwm` 组件 |
| **Sprinkler latching valve 配置移除** | 🟡 注意 | `pump_pulse_duration` 等配置项已移除，需改用 `switch.hbridge` |
| **Web Server URL 改为 entity 名称** | 🟢 低 | 旧 URL (`/sensor/temperature_sensor`) 仍可用至 2026.7.0；entity/area 名不能含 `/` |
| **HM3301 AQI 迁移至共享 aqi 组件** | 🟢 低 | 现有 `aqi:` 配置兼容，但实现已与 `pmsx003` 共享 |
| **MMC5603 `auto_set_reset` 默认启用** | 🟢 低 | 温度补偿默认开，读频率上限从 150Hz 降至 75Hz |
| **Ultrasonic `timeout` 选项废弃** | 🟢 低 | 固定 80ms timeout，选项将于 2026.8.0 移除 |
| **ESP32 Hosted `update` 需 `type:` 字段** | 🟡 注意 | 需加 `type: embedded` 或新 `type: http` |

## 4. 新功能实战：WiFi 漫游配置示例

### 基础配置（默认启用漫游）

```yaml
wifi:
  ssid: !secret wifi_ssid
  password: !secret wifi_password

  # 以下为默认行为，无需额外配置：
  # post_connect_roaming: true  （默认值，可不写）
```

### 多 AP 场景（推荐配置）

```yaml
wifi:
  ssid: !secret wifi_ssid
  password: !secret wifi_password

  # 多个 AP（ESPHome 会自动尝试连接列表中的 AP）
  ap:
    ssid: !secret wifi_ssid_2
    password: !secret wifi_password_2

  # 自动漫游配置（默认 true，可省略）
  post_connect_roaming: true

  # 手动 RSSI 阈值（可选，默认不设置）
  # 仅当信号低于阈值时才考虑漫游
  # minimum_rssi: -70
```

### 禁用漫游（特殊场景）

```yaml
wifi:
  ssid: !secret wifi_ssid
  password: !secret wifi_password

  # 禁用自动漫游（当设备使用 802.11k/v 漫游时自动关闭）
  post_connect_roaming: false
```

### 配合 802.11k/v 漫游（企业级）

```yaml
wifi:
  ssid: !secret wifi_ssid
  password: !secret wifi_password

  # 启用 802.11r Fast BSS Transition（快速漫游）
  fast_connect: false  # 使用 802.11r 时建议关闭 fast_connect

  # 注意：post_connect_roaming 在检测到 802.11k/v 配置时会自动关闭
```

### 完整示例（带 MQTT + API 加密）

```yaml
substitutions:
  device_name: living_room_sensor
  friendly_name: "客厅传感器"

esphome:
  name: ${device_name}
  friendly_name: ${friendly_name}
  comment: "ESP8266 with WiFi roaming"

wifi:
  ssid: !secret wifi_ssid
  password: !secret wifi_password
  ap:
    ssid: "${friendly_name} Fallback"
    password: !secret wifi_password

  # 自动漫游（连接后自动切换到更优 AP）
  post_connect_roaming: true

  # 配网超时
  provisioner:
    timeout: 5min

api:
  encryption:
    key: !secret api_encryption_key

ota:
  - platform: esphome
    # SHA256 认证默认启用，无需额外配置

sensor:
  - platform: dht
    pin: D2
    temperature:
      name: "${friendly_name} Temperature"
    humidity:
      name: "${friendly_name} Humidity"
    update_interval: 60s

debug:
  sensors:
    - platform: debug
      free:
        name: "Heap Free"
      partition:
        name: "Partition Info"
```

## 5. 升级后常见问题排查

### Q1：编译报错 `api: password: is not a supported configuration`

**原因：** `password:` 认证已被移除。
**解决：** 迁移至加密认证：

```yaml
api:
  encryption:
    key: !secret api_encryption_key
```

### Q2：OTA 更新失败，报错 MD5 相关

**原因：** 旧版本 ESPHome 无法 OTA 到 2026.1.0+（MD5 已废弃）。
**解决：** 确保 ESPHome 主机端版本 >= 2025.10.0，再执行 OTA。必要时先串口刷写一次。

### Q3：切换到 ESP-IDF 后编译报错，提示某组件不支持

**原因：** 该组件仅有 Arduino 实现，尚无 ESP-IDF 兼容版本。
**解决：** 显式使用 Arduino 框架：

```yaml
esp32:
  board: esp32dev
  framework:
    type: arduino
```

**常见需用 Arduino 的组件：**
- `heatpumpir`（红外空调控制）
- `midea`（美的空调）
- WLED Effect（light 平台下的 UDP 实时控制）

### Q4：ESP8266 设备升级后串口不可用/Serial 不工作

**原因：** 未使用的 `Serial`/`Serial1` 对象在构建时被排除。
**解决：** 在配置中添加：

```yaml
esp8266:
  enable_serial: true   # 启用 Serial（USB CDC）
  # enable_serial1: true  # 如需 Serial1（GPIO2）
```

### Q5：Web Server 旧 URL 失效

**原因：** Web Server URL 格式从 `object_id` 改为 `entity name`。
**解决：** 
- 更新书签/脚本中的 URL
- 旧 URL 仍可在 2026.7.0 前兼容使用
- 注意：entity 名称不能含 `/` 字符

### Q6：ESP32 固件体积反而变大？

**原因：** 如果配置使用了 Arduino 特有组件，切换到 ESP-IDF 后需要同时替换对应组件。
**解决：** 参考[迁移指南](https://esphome.io/guides/esp32_arduino_to_idf/)，替换为 ESP-IDF 兼容替代品。

### Q7：蓝牙代理/C3 蓝牙设备不稳定

**原因：** 2026.1 之前 ESP32-C3 蓝牙代理不可靠。
**解决：** 该问题已在 2026.1 中通过调度器调优和内存优化修复，升级后应已解决。若仍有问题，检查 WiFi 信号质量。

### Q8：设备运行中 heap 仍然偏低

**诊断：**
```yaml
debug:
  sensors:
    - platform: debug
      free:
        name: "Heap Free"
      largest_free_block:
        name: "Largest Free Block"
      fragmentation:
        name: "Heap Fragmentation"
```

## 6. 对现有项目的影响评估

### 影响等级判断

| 你的情况 | 影响评估 | 推荐操作 |
|---|---|---|
| **ESP8266 设备，配置简单**（sensor + switch） | 🟢 正面影响 | 升级后稳定性提升，heap 翻倍 |
| **ESP32 设备，无 Arduino 专用组件** | 🟢 正面影响 | 固件体积-40%，编译更快，框架自动切换 |
| **ESP32 设备，使用 heatpumpir / midea** | 🟡 需修改 | 加 `type: arduino` |
| **配置中有 `api: password:`** | 🔴 阻断 | 升级前必须迁移至 `encryption:` |
| **WiFi 多 AP 漫游需求** | 🟢 新功能可用 | 升级后自然获得 |
| **使用 sprinkler latching valve** | 🟡 需修改 | 迁移至 `switch.hbridge` |
| **大量实体的大型设备** | 🟢 正面影响 | 零拷贝 + object_id 移除，效率大幅提升 |
| **ESP32-C3 蓝牙代理用户** | 🟢 正面影响 | 可靠性问题已修复 |
| **Web Server URL 直接引用** | 🟢 低风险 | 旧 URL 兼容至 2026.7.0 |

### 总结

| 维度 | 评估 |
|---|---|
| **安全性** | ✅ 强制加密 + SHA256，更安全 |
| **性能** | ✅ ESP8266 heap x3，ESP32 体积-40%，编译 2-3x |
| **稳定性** | ✅ WiFi 漫游解决 AP 粘滞问题 |
| **兼容性** | ⚠️ 少量 Breaking Changes，均有明确迁移路径 |
| **升级建议** | **强烈建议升级**，Breaking Changes 均提前 deprecated 有提示 |
